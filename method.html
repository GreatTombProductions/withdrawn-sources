Method & sources

What this tool does, exactly: it extracts DOI and PMID identifiers from text you paste, matches them against a dated snapshot of the Retraction Watch Database, and — on request — checks Crossref member metadata live for identifiers the snapshot does not contain.

Source & snapshot

The dataset is the Retraction Watch Database, maintained by Retraction Watch and made publicly available by Crossref through gitlab.com/crossref/retraction-watch-data (CSV, regenerated each working day). This site ships a pinned snapshot; the receipt below identifies exactly which snapshot — hash and date — so any number on this site can be traced to a specific edition of the source file.

What is extracted, and what is not

  • Detected: DOIs written as 10.xxxx/… (including https://doi.org/… and doi: forms), and PubMed IDs in the common label forms (PMID: 12345678, PubMed ID 12345678) and PubMed URLs.
  • Not detected: author–year citations, plain titles, ISBNs, and anything else without a machine-readable identifier. For those, use the database search by title, author, or journal.
  • DOIs may themselves contain parentheses (e.g. 10.1016/S0140-6736(97)11096-0); the extractor keeps balanced parentheses and strips surrounding punctuation so these survive intact.

How a match is made

  • DOIs are compared case-insensitively after stripping URL/doi: prefixes. Both the original paper's DOI and the notice's DOI are indexed — either one resolves to the record.
  • PMIDs are compared as digits, matching both the original-paper and notice PMID fields.
  • A paper can have multiple notices over time (e.g. a 2004 correction and a 2010 retraction). All matching records are shown, oldest first — the record here is the notice trail, not a single verdict.

Coverage & caveats (read these)

  • “No notice found” is not “not retracted.” The database is the most complete public record of retractions but is not exhaustive; Crossref states that corrections and expressions of concern are less comprehensively covered than retractions.
  • The snapshot is dated. Retraction Watch updates the source each working day; notices published after the snapshot date cannot appear here. Newer records are exactly why the per-identifier live Crossref check exists.
  • Live Crossref checks read member-deposited metadata only. Crossref's per-work update-to field is supplied by publishers and is incomplete — a retracted work can show no update entry (the 1998 Wakefield paper is a live example). A “no update notice” result there is a statement about the metadata, not about the paper.
  • Record semantics come from Retraction Watch. “Nature” is the notice type (Retraction, Expression of concern, Correction, Reinstatement); “reason” is Retraction Watch's controlled vocabulary. Read them as the database's terms, not this site's judgment.
  • Nothing leaves your browser except the live Crossref checks you click (a direct request from your browser to api.crossref.org), and pasted text never leaves it at all.

Attribution

Data: Retraction Watch Database (Retraction Watch / The Center for Scientific Integrity), made publicly available by Crossref at gitlab.com/crossref/retraction-watch-data; updated each working day. Field semantics follow the Retraction Watch Database user guide. Live checks read Crossref REST API member metadata. This site is a static, non-commercial portage layer over those public sources; it is not affiliated with Retraction Watch or Crossref.

How it's built

pipeline/fetch.py    download the snapshot + write the pinned receipt (sha256)
pipeline/build.py    parse → lookup index (DOI/PMID) + record shards + search index
pipeline/extract.py  identifier extraction (Python twin of frontend/extract.js)
tests/               shared extraction cases (both languages) + data-contract + browser smoke

The extraction rules are one coupled pair implemented twice — Python for the pipeline, JS for your browser — held to one shared case table plus a differential parity pass (zero diffs allowed). See the repository README for the exact commands.
